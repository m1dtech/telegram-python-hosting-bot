## نبذة

يحتوي المستودع على تطبيق بوت Telegram مكتوب ببايثون لإدارة طلبات استضافة ملفات بوتات المستخدمين. يتيح مسار الشيفرة استقبال ملفات Python بامتداد `.py`، وتسجيل الطلبات ومراجعتها، ثم تشغيل العمليات وإدارة سجلاتها وملفاتها. ويستخدم Docker لإنشاء حاويات مخصّصة للمستخدم عند توفره، مع تخزين بيانات التشغيل في مجلدات محلية.

الوصف أعلاه يقتصر على ما يظهر في `main.py` وملفات النشر. لا يثبت وجود دعم فعلي لرفع أو تشغيل JavaScript أو PHP أو ملفات ZIP؛ معالج المستندات الظاهر يقبل ملفات `.py` فقط. كما أن وجود مكوّن Docker لا يثبت أن العزل محكم أو أن التطبيق آمن.

## الوظائف الظاهرة في المصدر

- واجهة Telegram وأوامر للمستخدم تشمل البدء والإلغاء، رفع ملف Python، متابعة الملفات والحساب والنقاط والمتجر والدعم.
- تسجيل المستخدمين والملفات والطلبات والإعدادات في `bot_database.json`، مع بيانات عن النقاط وحالات الملفات والطلبات.
- آليات إدارية ظاهرة لمراجعة طلبات الرفع والطلبات، وإدارة المستخدمين والاشتراكات وإرسال الرسائل وعرض الإحصاءات.
- تشغيل عمليات الملفات ومتابعتها وإيقافها، مع حفظ سجلات، وإدارة مساحة تخزين يحددها المصدر.
- إنشاء حاويات Docker للمستخدمين بصورة Python، ومحاولة تثبيت الاعتماديات المستخرجة من ملفات Python المرفوعة.
- نسخ احتياطي تلقائي إلى قناة Telegram مضبوطة في المصدر، ونسخ لبعض الملفات والسجلات إلى أرشيفات محلية.

هذه قائمة بالمسارات الموجودة في الشيفرة، وليست ضمانًا بأن كل ميزة مكتملة أو تعمل كما هو متوقع.

## بنية الملفات ذات الصلة

- `main.py` — منطق البوت وإدارة البيانات والملفات والعمليات والحاويات.
- `requirements (6).txt` — قائمة اعتماديات Python المثبتة الإصدارات.
- `Dockerfile` و`start.sh` — إعداد صورة حاوية ونص بدء الخدمة كما هو معرف في المستودع.
- `fly.toml` — إعداد نشر Fly.io، بما فيه إعدادات آلة ذات صلاحيات مرتفعة ووحدة تخزين.
- `bot_database.json` — ملف قاعدة بيانات متتبع في المستودع؛ لا ينبغي نشر بيانات تشغيل أو بيانات شخصية فيه.

لا يوجد README سابق أو ملف ترخيص في جذر المستودع كما ظهر في الملفات المفحوصة. لذلك لا يحدد هذا المستودع ترخيصًا؛ تحقّق من صاحب المشروع قبل إعادة الاستخدام أو التوزيع.

## المتطلبات وما يمكن استنتاجه عن الإعداد

تستهدف صورة `Dockerfile` الرسمية Python 3.12 على صورة `slim`، وتثبّت أدوات بناء وDocker، ثم تثبّت محتويات `requirements (6).txt` وحزمة Docker Python. ويشير `start.sh` إلى بدء Docker daemon ثم تشغيل `main.py`. أما `fly.toml` فيصف نشرًا يعتمد على Docker ومجلد تخزين دائم، ويطلب تشغيلًا بصلاحيات `privileged` وموارد كبيرة.

توجد فجوة اعتماديات مهمة: يستورد `main.py` الوحدة `dotenv`، لكن `python-dotenv` غير مدرجة صراحةً في ملف المتطلبات، ولا يضيفها `Dockerfile` صراحةً. كذلك يستخدم المصدر قيمتي الإعداد `BOT_TOKEN` و`ADMIN_ID` كثوابت داخل `main.py`؛ استدعاء `load_dotenv()` وحده لا يجعل هاتين القيمتين إعدادًا من البيئة. ويظهر `USER_DATA_DIR` في إعداد Fly، بينما يعيّن المصدر مسار بيانات المستخدمين محليًا بنفسه. لذلك لا يمكن اعتبار إعدادات البيئة أو النشر موصولة بالكامل.

## البيانات والتخزين والنسخ الاحتياطي

يستخدم التطبيق ملف JSON محليًا لبيانات البوت، ومجلدات للملفات المرفوعة والسجلات والنسخ الاحتياطية، إضافة إلى مجلد بيانات للمستخدمين. يتضمن المصدر نسخة احتياطية دورية تُرسل إلى قناة Telegram، كما ينشئ نسخًا محلية لبعض الملفات. لا تتضمن المستودع تعليمات موثوقة لاستعادة نسخة احتياطية أو سياسة احتفاظ وخصوصية مكتملة. تعامل مع قاعدة البيانات والملفات والسجلات والنسخ الاحتياطية بوصفها بيانات حساسة، وقيّد الوصول إليها وحدد سياسة احتفاظ واستعادة قبل أي استخدام.

## تنبيه أمني وحدود المشروع

- يحتوي المصدر على قيمة ثابتة لمتغير `BOT_TOKEN` ومعرّف ثابت لمتغير `ADMIN_ID`. لا تُدرج القيم هنا أو في سجلات عامة؛ أخرجها إلى مخزن أسرار آمن ودوّر الرمز فورًا إذا كان فعّالًا أو سبق نشره.
- يقبل البوت ملفات Python من المستخدمين ويثبت حزمًا ويشغّل عمليات. هذا تنفيذ لكود واعتماديات غير موثوقة، وقد يعرّض البيانات والمضيف والشبكة للخطر.
- يستخدم إعداد Fly وضع `privileged` ويشغّل Docker daemon داخل التطبيق. كما يحتوي المصدر على مسار بديل غير معزول عند غياب Docker؛ لذلك لا تصف النظام بأنه آمن أو معزول بالكامل، ولا تشغّله على مضيف أو حساب يحوي بيانات مهمة.
- تراجع إعدادات Docker وحدود الذاكرة والتخزين والصلاحيات والشبكة قبل النشر، واختبر حدود الموارد وسيناريوهات إساءة الاستخدام في بيئة منفصلة. لا تعتمد على حدود الحاويات الحالية باعتبارها ضمانًا أمنيًا.
- ملف قاعدة البيانات متتبع في المستودع وقد يكون ذا طبيعة تشغيلية أو شخصية؛ أزل أي بيانات فعلية من التحكم بالإصدارات، وراجع تاريخ Git وسياسة النسخ الاحتياطي والصلاحيات.
- النسخ الاحتياطي إلى Telegram قد ينقل قاعدة البيانات والملفات والسجلات خارج الخادم؛ تحقق من صلاحيات القناة والمستلمين والاحتفاظ والخصوصية قبل تفعيله.
- إعداد Fly يعلن خدمة HTTP على منفذ داخلي، بينما نقطة التشغيل الظاهرة تستخدم استطلاع Telegram ولا يظهر في المصدر خادم HTTP مقابل؛ يلزم حسم هذا التعارض والتحقق منه قبل الاعتماد على النشر.
- لم يُجرَ تدقيق تشغيل أو اختبار أمني أو اختبار عزل أو اختبار استعادة. هذا المستودع غير موثق بما يكفي لإثبات ملاءمته للإنتاج.
